# t_aw9523 — AW9523 IO Expander Validation Test

**Date**: 2026-07-29
**Status**: approved

## Purpose

A standalone debug test project (`debug/t_aw9523/`) that validates all 16 GPIO pins of the AW9523BTQR I2C IO expander on the DeepStoa v1 board. Focused purely on the IO expander — no display integration.

## Project Structure

```
debug/t_aw9523/
├── CMakeLists.txt          # ESP-IDF project, EXTRA_COMPONENT_DIRS → aw9523
├── main/
│   ├── CMakeLists.txt      # Register t_aw9523.c, PRIV_REQUIRES aw9523
│   └── t_aw9523.c          # Test firmware
└── sdkconfig.defaults      # Stack size 8192, WDT timeout 120s
```

## Test Sequence

### Phase 1: I2C & Identity
- `aw9523_init()` with board default pins and address
- `aw9523_get_chip_id()` — expect 0x23
- FAIL if init fails or chip ID mismatch

### Phase 2: Output Pin Walk
For each of the 14 output-capable pins:
- P0.0, P0.1, P0.2, P0.3, P0.4 (unused on board)
- P0.6 (LCD_SDI), P0.7 (LCD_SCLK)
- P1.0, P1.1, P1.2, P1.3, P1.7 (unused on board)
- P1.4 (LCD_CS), P1.5 (LCD_DC)

For each pin:
1. Configure as output (via port direction register)
2. Set HIGH → read back input register → verify HIGH
3. Set LOW → read back input register → verify LOW
4. Leave at LOW (safe state)

### Phase 3: Input Pin Read
Read the two input-only pins (configured as input by aw9523_init):
- P0.5 (LCD_INT) — read and log state
- P1.6 (LCD_BUSY) — read and log state

No assertion on values — just log what's observed.

### Phase 4: Port-Level Operations
- Write 0xAA to P0 via `aw9523_write_port(0, 0xAA)` → read back via `aw9523_read_port(0)`
- Write 0x55 to P1 via `aw9523_write_port(1, 0x55)` → read back via `aw9523_read_port(1)`

### Phase 5: Restore Safe State
Re-apply display-safe defaults matching `aw9523_init()`:
- P0: only INT(P0.5) as input, all others output
- P1: only BUSY(P1.6) as input, CS(P1.4)=high, others output low

### Phase 6: Summary
- Print per-pin PASS/FAIL table
- Print overall result (PASS if all output pins pass walk test and port test)

## Safety Considerations

- CS (P1.4) held high (inactive) except during its brief test window
- All output pins left at LOW (safe/neutral) after individual test
- No SPI bit-banging — pure GPIO, no risk of display corruption
- Port-level test uses bit patterns that restore to safe state afterward

## Dependencies

- `drivers/aw9523` — existing component (I2C GPIO expander driver)
- `boards/esp32s3/deepstoa_v1.h` — existing board pin definitions
- ESP-IDF `driver` component — I2C master, GPIO
